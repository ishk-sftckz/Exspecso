# Distinguish evidence failure from operational blocking

A failed Evidence Contract moves a Task to `verification-failed`; beginning an approved Correction Loop returns it to `in-progress`, and another failed attempt returns it to `verification-failed`. A workflow obstruction such as a Git failure, artifact persistence failure, unavailable required tool or dependency, or required human decision moves the Task to `blocked` and records a Resume Checkpoint. Clearing the obstruction permits `blocked` to return to `in-progress`. Evidence that passes before checkpoint persistence fails remains provisional and cannot make the Task `done`; it may be reused on retry only if its complete Evidence Boundary and Git state still match. Task completion requires both accepted evidence and a durably persisted Verified Checkpoint.
