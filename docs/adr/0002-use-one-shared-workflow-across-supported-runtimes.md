# Use one shared workflow across supported runtimes

Claude Code, OpenAI Codex, and OpenCode will expose the same Exspecso operations and operate on one canonical artifact model through runtime-specific adapters. Operations use identical hyphenated identifiers such as `exspecso-start`; `/exspecso-start` is the preferred invocation wherever the host exposes skills through slash commands, while a host's native skill invocation is an allowed fallback when slash invocation is unavailable. The Codex adapter targets Desktop, CLI, and IDE rather than one Codex surface. `init` installs only the selected adapters into the current repository by default and never silently mutates user-global runtime configuration; global installation may be added later as an explicit option. Adapters remain thin entry points into the shared CLI and deterministic helper: hooks may provide optional convenience, but correctness does not depend on hooks, MCP, or runtime-owned orchestration. The shared contracts and conformance flow will account for all three runtimes from the beginning, while Codex provides the first end-to-end proving runtime; Claude Code and OpenCode follow against the proven contract, and all three must pass conformance before V1 is complete. This avoids migration and runtime-owned truth while accepting the constraint that native runtime capabilities must degrade gracefully without changing workflow semantics.
