# Revise approved work with explicit impact analysis

`/exspecso-update` never edits an approved revision in place. It creates a candidate revision and a Revision Impact Record for confirmation, then applies the smallest safe invalidation. Editorial-only changes may carry evidence forward explicitly when semantic fingerprints are unchanged. Verification changes retain implementation but invalidate affected Task evidence, Closure Reports, and Final Reviews. Plan or implementation-scope changes supersede the old Plan and invalidate affected Tasks and their dependents. Intent or Acceptance Criterion changes move the Specification to `needs-revision` and make affected downstream artifacts historical until the new revision is approved. Unclear impact requires human classification. Direct edits to approved contracts are detected as drift and reconciled through the same revision process rather than silently accepted.
