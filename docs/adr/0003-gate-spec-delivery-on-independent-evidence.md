# Gate Specification delivery on independent evidence

Exspecso will advance an approved Specification through a bounded Delivery Loop, but no Task or Specification is complete merely because a builder claims success or code exists. Completion requires the predeclared Evidence Contract, a Verified Checkpoint, applicable Closure Verification, closed traceability, and logically independent Final Review. Each accepted checkpoint uses a stable Task-scoped revision identifier recorded in both the Task evidence and its Git commit footer, allowing the helper to resolve the actual commit without embedding a self-referential commit SHA; later correction creates a new checkpoint revision and preserves prior evidence as history. Accepted completion remains valid only while its Evidence Boundary still matches the approved intent, verification contract, and relevant repository state: relevant drift reopens the affected Task and invalidates superseded evidence, while proven-unrelated drift does not. This trades some execution speed and simplicity for reliable, reviewable delivery.
