# Keep one current contract and Git-backed revision history

Each entity has one stable canonical path, such as `spec.md`, `plan.md`, or `task-NNN.md`, representing its current revision. A proposed change remains a clearly non-canonical Revision Proposal with a Revision Impact Record until Content-bound Approval atomically promotes it into the stable paths and commits the transition. Prior contract versions remain reconstructible from their recorded Git commits and fingerprints rather than coexisting as competing current files. Evidence records—including Verified Checkpoints, Correction Episodes, closure results, and Final Reviews—are append-only or uniquely revisioned because later decisions cite them; a singular report may project its latest result while retaining earlier entries. Cold-start reads current canonical files and resolves Git-backed history only when referenced evidence requires it.
