# Use explicit policy precedence with hard safety invariants

Effective Configuration resolves built-in defaults, checked-in `exspecso.config.json`, approved artifact declarations, permitted invocation options, and hard Exspecso safety invariants in increasing authority. Runtime adapters cannot define policy. Artifact declarations may strengthen project policy but require explicit approval and rationale to weaken it; invocation options may select target, execution pacing, or output format but cannot bypass approval, evidence, review, Git, or WIP gates. Gitignored local preferences affect presentation and runtime convenience only. Secrets are referenced by environment-variable name rather than stored. Correctness-affecting policy changes are committed, fingerprinted, and impact-assessed, while diagnostics and relevant evidence record the effective configuration used.
