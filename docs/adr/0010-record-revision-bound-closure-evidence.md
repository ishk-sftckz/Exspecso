# Record revision-bound closure evidence

Each Specification owns a canonical `closure-report.md` whose current result is `pass`, `fail`, or `not-required`. The report binds its result to the applicable Specification and Plan revisions, covered Acceptance Criteria, accepted Task checkpoint IDs, verification-contract fingerprint, and tested Git state. Specification status summaries only project this evidence, and Final Review consumes it. A relevant later checkpoint or repository change inside the Evidence Boundary invalidates the current result and requires closure verification again while retaining prior results as history. A failure reopens the smallest traceable Task or Acceptance Criterion; a failure that cannot be mapped safely to approved scope stops for Specification revision or human judgment.
