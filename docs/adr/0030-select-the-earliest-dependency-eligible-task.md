# Select the earliest dependency-eligible Task

Plan order expresses selection preference while explicit dependencies provide hard execution gates. The Delivery Loop selects the earliest `ready` Task whose dependencies have accepted Verified Checkpoints, allowing a later independent Task when an earlier one is dependency-waiting or blocked. A Task already `in-progress`, `verification-failed`, or carrying an unfinished Correction Episode must be resumed or resolved before another activates, preserving the global V1 WIP limit of one. Strict sequencing is expressed through dependencies rather than list position. Done Tasks are skipped, cancelled Tasks remain required until an approved Plan revision removes them, and absence of an eligible Task returns a typed `blocked` result identifying the preventing dependency or decision.
