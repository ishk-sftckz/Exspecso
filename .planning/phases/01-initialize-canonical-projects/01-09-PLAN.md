<feasibility_evidence>
Planning inspected Node v20.19.5 on darwin: fs/promises exports no openat, renameat, unlinkat, mkdirat, fchdir, or flock. The documented rename operation accepts paths, and FileHandle supplies file operations rather than relative namespace replacement. Therefore O_NOFOLLOW on a whole path, repeated lstat/realpath, or ordinary rename cannot by itself bind all intermediate directories. [Node 20 filesystem API](https://nodejs.org/docs/latest-v20.x/api/fs.html#fspromisesrenameoldpath-newpath).

Node-API supports native addons with an ABI-stable C interface; this makes a same-package binding a concrete proposal, not proof that this repository already builds or packages it. [Node-API](https://nodejs.org/api/n-api.html). The local header /opt/homebrew/include/node/node_api.h exists; compiler usability and the complete binding have not been proven in planning. No native implementation was run or accepted.
</feasibility_evidence>

<interfaces>
Proposed provider: native/contained-fs.cc uses the C Node-API directly, without adding node-addon-api, node-gyp, or an npm dependency. native/build.mjs invokes the locally available C++ compiler with an argument array and a checked Node header directory. An explicit EXSPECSO_NODE_INCLUDE_DIR may locate installed headers; it is build configuration, never canonical project state. Output is dist/native/contained-fs.node. The package remains one npm package and the semantic implementation remains TypeScript; native code owns only OS filesystem mechanics.

ContainedFilesystem owns an opaque root descriptor plus opened directory/target handles. Its operations cover no-follow component walking, descriptor reads/stat, temporary creation/write/sync, directory-relative replace/unlink, directory publication, listing, and empty-directory cleanup. Bindings are not arbitrary numeric file descriptors supplied by callers. All canonical schema, hash, recovery, selection, and journal decisions stay in existing TypeScript modules. Keep the 01-08 ownership protocol; replace its underlying namespace primitives rather than adding another lock authority.
</interfaces>
