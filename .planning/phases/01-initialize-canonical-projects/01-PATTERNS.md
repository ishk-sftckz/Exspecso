**Analog:** None; this is the phase's core product-specific durability mechanism.

**Transaction pattern to implement** (`01-RESEARCH.md:235-250`): stage every output under a private directory on the repository filesystem; journal transaction ID, allowed target paths, preimage hashes, staged hashes, and committed step; validate staged contents; flush and promote with rename; then clean up only validated staging debris.

**Failure policy:** Before any write, reject a missing Git root, target traversal/symlink ambiguity, malformed current artifacts, unowned adapters, changed managed adapters, or any conflict in the full selected change set. Never use an unbounded recursive cleanup.

## Shared Patterns

### Repository-root containment

**Source:** `01-CONTEXT.md:35-40` and `01-RESEARCH.md:180-204`.

Apply to every file read, staged path, adapter destination, and recovery path: resolve the containing Git root before paths are derived; ensure each target remains beneath it; never invoke `git init` automatically.

### Plan, validate, then commit

**Source:** `01-RESEARCH.md:206-221`.

Apply to `init`, adapter refresh, and all canonical writes: one immutable plan, aggregate all diagnostics/conflicts, and call the transaction only when the entire mutation set is safe. No best-effort per-file writes.

### Canonical state versus adapters

**Source:** `docs/specs/SPEC-exspecso-v13-phase-oriented-workflow.md:27-35`; `docs/research/runtime-command-naming.md:79-91`.

Canonical truth is human-readable `.exspecso` JSON/Markdown. Runtime files are generated adapters only; their native syntax may differ, but their operation ID, arguments, behavior, and artifact contracts cannot.

### Structured validation and error handling

**Source:** `01-CONTEXT.md:35-40`; `01-RESEARCH.md:259-267`.

Use Zod `safeParse` at parser boundaries and transform schema, relationship, duplicate-ID, path, hash/preimage, and recovery failures into one diagnostic collection. Never repair canonical artifacts while reporting errors.

### Safe generated-file ownership

**Source:** `01-CONTEXT.md:29-33`; `01-RESEARCH.md:223-233`.

A managed header/body fingerprint is the full ownership record. Do not add an adapter-state manifest, auto-select detected agents, overwrite a local edit, or delete a deselected adapter.
